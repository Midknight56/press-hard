## Tests that failed first

- `core/tests/lines.test.ts`: 7 of 7 failed before the line marks existed (`changedLines` undefined, no `data-lines` attribute).
- `app/tests/blind-test.test.ts`: 10 of 10 failed, each on the old text or the missing element (shown in the rows above).
- `e2e/blind-test.spec.ts` on the old build: 7 failed (rows 1, 2, 4, 8 and 14; row 1 three times) and 7 passed (rows 15 to 18, row 2 at 1920x1080, and row 3).
- Row 3 first passed for the wrong reason: `toBeHidden` waited until the loop moved on to its next step. The check now reads the state once. It then failed at both sizes, 2 of 2, before the fix.

## Test changes to note

- `core/tests/exports.test.ts`: `findChangedLines` was added to the list of exported functions, because the design now has this function. No check was removed.
- `core/tests/lines.test.ts`: before the test first passed, its marks pattern was widened to allow capital letters, because the line name `sealedAt` has one. It still allows only line names and 64 character hex digests.
- `app/tests/blind-test.test.ts`, row 7: the first version expected the word "optional" inside the label text, and it failed on the old code. The existing `app/tests/form.test.ts` expects the label text to be the label alone, so the word is drawn by CSS and the test now checks `data-optional` and an unchanged label. The browser check of the drawn word (`" optional"` after Fuel, `none` after Item) was written after the fix, so it was not seen failing on the old code.
- The `data-locked` check of row 6 sits after the first line of its test, so on the old code it never ran (that line failed first). Kiro did not change the number check in `firstMissing`.

## Verify

`npm run verify:e2e` exit 0: typecheck and lint clean, 270 core tests, 31 mcp tests, 450 app tests and 79 browser tests pass (headless Chromium, `--mute-audio`).
